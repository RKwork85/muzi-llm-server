# M1｜UI 协议、Block 模型与 Schema

## 阶段目标
让一条消息承载文本、代码、表格、图表、工具结果和交互块，保持稳定顺序与可扩展性。

## 前置条件
M1 无前置阶段，先完成现状审计。

## 详细工作包
### M1-T01 现状审计
- 工作内容：清点 message/chatRunId/serverRunId、SSE、Plan 交互表、前端消息结构；标注兼容风险和既有迁移。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M1-T02 协议规范
- 工作内容：定义 muzi.ui.v1：MessageEnvelope、Block、ComponentBlock、InteractionRef、ErrorBlock；明确 ID、时间戳、排序、状态、来源、版本。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M1-T03 Block 类型
- 工作内容：text、markdown、code、table、chart、tool_result、component、status、fallback；区分内容与业务操作。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M1-T04 Schema 与校验
- 工作内容：使用 JSON Schema/Pydantic 定义 discriminated union、严格字段、大小/深度/数组限制、可扩展字段策略。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M1-T05 存储设计
- 工作内容：消息正文与 block 顺序、协议版本、schema_version、不可变快照；先加法迁移并提供旧消息适配。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M1-T06 API 契约
- 工作内容：定义消息读取、创建/追加和错误格式；统一 trace_id/run_id/message_id/block_id 关联。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M1-T07 兼容降级
- 工作内容：未知 block 用安全占位文本；旧客户端读取旧消息仍正常，避免强制切换。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

## 关键验收标准
- [ ] 一条消息含 text+chart+choice 三块并保持顺序
- [ ] 非法组件、超大嵌套、未知版本被拒绝或安全降级
- [ ] 旧消息历史可正常加载，数据库迁移可回滚
- [ ] 不同用户无法读取彼此消息块

## 主要风险与防护
- 协议漂移：服务端 schema、客户端类型、测试样例统一生成或双向契约测试。
- 权限绕过：所有状态变更都在服务端复核，UI 组件不是授权凭证。
- 兼容性：加法迁移、feature flag、旧版 fallback、回滚路径。
- 竞态与重放：稳定 ID、事务、版本号、幂等键和事件序列。

## 统一工程约束
- 以现有 FastAPI / Vue 3 / PostgreSQL / Redis / SSE 为基线，先审计再修改；不得以规划推断当前实现状态。
- 后端是身份、授权、交互状态和事件序列的唯一可信来源；模型输出一律视为不可信输入。
- 协议必须版本化，旧客户端能安全降级；所有写操作具备鉴权、资源归属、幂等和审计。
- 每个阶段均需单元、集成、端到端、安全、兼容性测试；没有证据不得标记 ACCEPTED。
- 不擅自修改 Ask/Plan/Agent 现有语义，不以新 UI 协议替代 Runtime 权限边界。

## 阶段交付要求
- 提交架构决策记录（ADR）、协议/数据库迁移说明、测试报告、演示录屏或截图、回滚方案。
- 明确 CODE PASS、UAT PASS、PRODUCTION READY 三种不同状态。
- 每项验收需列出可复现命令、测试用例编号、预期结果、实际证据和已知限制。
