# M6 · 局部更新与版本控制 — 执行报告

状态：**CODE_PASS**（就地修订 + 版本 diff + 回滚已落地；浏览器端焦点/草稿保持无自动化用例）

## 1. 阶段目标

让已展示组件可被安全增量更新，同时保持状态一致、用户输入不丢失。

## 2. 现状审计结论

- **受限更新协议**：`ActionType` 只允许 `append`（step_add）、`replace`（step_edit/assumption_edit/goal_edit）、`remove`（step_remove/constraint_remove）、`reorder`（step_reorder）、`rollback`（revision_rollback）等确定性子集，**不允许任意脚本或 JSONPath 写入**。
- **乐观并发**：`plan_revision` 作为 `base_revision`，`_store_revision` 用 CAS（`WHERE current_revision=current`）拒绝旧 revision 更新；前端 `applyPlanAction` 携带 `plan_revision`。
- **就地修订**：修订动作「只改内容、不改状态」，审阅卡处于 `awaiting_approval` 时用户改完可直接「确认计划」，不强制打回 drafting。
- **版本与 diff**：`plan_revisions` 保留不可变快照，`compute_plan_diff` 对比 `goal/status/assumptions/decisions/steps/constraints`；`revision_rollback` 把目标历史版本派生为新版本并回到 drafting。

## 3. 关键交付物

### 3.1 修订纯函数（`app/planning/revisions.py`）

```text
sync_assumptions / edit_assumption / confirm_assumption / reject_assumption   （假设 M3）
validate_step_dependencies / validate_step_order                              （依赖/成环/顺序）
add_step / edit_step / remove_step / split_step / merge_step / reorder_step   （步骤 M4）
rollback_snapshot / compute_plan_diff                                        （版本 M6）
```

影响分析：`_find_affected` 用关键词匹配定位受假设变更影响的决策键与步骤 id，前端 `PlanReviewPanel` 展示「本次修改可能影响」。

### 3.2 就地修订编排（`sql_store.py::apply_action`）

`_PLAN_REVISION_ACTIONS`（假设/步骤/目标/约束类动作）走 `compute_revision_changes` → `_revise` → `_store_revision`，实时更新当前快照并落新版本，状态保持不变。

### 3.3 前端合并（`PlanReviewPanel.vue`）

目标编辑、步骤增/改/删/拆分/上移下移、假设确认/修改/否定、历史版本 diff、回滚，全部通过 `emitAction` 走统一 `POST /plans/{id}/actions`，`block_id`（此处为 `step.id`/`assumption.id`）稳定，局部重渲染不重建整条消息。

## 4. 验收标准逐条核查

| 验收项 | 结果 | 证据 |
|---|---|---|
| 同一图表更新不重建整条消息 | 满足（等价） | 步骤/假设按 `target_id` 就地修订，不重建整条消息 |
| 旧 revision 不能覆盖新版本 | 满足 | `_store_revision` CAS + 前端 `plan_revision` 校验 |
| 非法 patch 不改变数据库状态 | 满足 | `compute_revision_changes` 失败抛 `PlanningPolicyError`，事务回滚 |
| 输入中的交互组件不会因无关更新丢失草稿 | 满足（代码层） | `InteractionRenderer` 的 `savedValue`/`draft` 隔离；但无 e2e 用例 |
| 重放 patch 后快照与实时结果一致 | 满足 | `plan_actions` 幂等 + `result_snapshot` 存储 |

## 6. 差距与风险

- **撤销历史不承诺全量可逆**：只提供「回滚到指定版本」，不提供逐动作 undo；文档已明确「不承诺所有更新都可逆」。
- **焦点/草稿保持**：就地修订后前端组件重新渲染，输入焦点与未提交草稿的保持逻辑依赖 `watch(savedValue)`，无自动化验证。
- **base_revision 语义**：当前用 `plan_revision`（计划级）而非 block 级 revision；对「同一计划内多 block 并发更新」的保护粒度是计划级，够用但非文档描述的 block 级 CAS。
