# M2 · Component Registry 与 Vue 动态渲染 — 执行报告

状态：**CODE_PASS**（前端注册表 + 未知组件降级已落地；无前端 e2e 自动化用例）

## 1. 阶段目标

建立可发现、可校验、可版本化的组件能力目录和安全渲染层。

## 2. 现状审计结论

- **服务端组件白名单**：`app/planning/contracts.py` 的 `InteractionType` 枚举是权威组件目录，模型只能从中选择，服务端据此校验并分发渲染。这是「服务端发现」的等价实现——组件清单由契约层固定，前端按 `type` 映射渲染组件。
- **前端组件注册表**：`src/modules/conversation/components/planning/interactionRegistry.js` 以 `Object.freeze` 冻结的映射表，只注册本地编写的受信组件。
- **动态渲染器**：`InteractionRenderer.vue` 用 `<component :is="renderer">` 动态解析，未知类型安全降级。
- **渲染安全**：组件只渲染 `props`，不执行模型输出的 HTML/JS/Vue 模板；文本一律 `safeText()` 截断，不 `v-html`。

## 3. 关键交付物

### 3.1 前端注册表（`interactionRegistry.js`）

```js
export const interactionComponentRegistry = Object.freeze({
  single_select: InteractionInput,
  multi_select: InteractionInput,
  text_input: InteractionInput,
  text_area: InteractionInput,
  form: FormCard,
  confirmation: InteractionInput,
  plan_review: PlanReviewPanel,
  plan_diff: PlanDiff,
  progress: InteractionStatusNotice,
  error: InteractionStatusNotice,
})

export const resolveInteractionComponent = (type) =>
  interactionComponentRegistry[type] || InteractionStatusNotice
```

### 3.2 渲染器（`InteractionRenderer.vue`）

- 顶部渲染 `prompt`/`description`，中间用 `<component :is="renderer">` 动态挂载，底部按类型渲染提交/跳过/确认按钮。
- `renderer` 来自 `resolveInteractionComponent`，未知 `type` 回退 `InteractionStatusNotice`，**不崩溃、不执行任意代码**。
- 组件 `props` 经 `Interaction` 契约（服务端）校验后返回，前端不再二次信任模型原始输出。

### 3.3 服务端校验链

`app/planning/runtime.py` 的 `InteractionOrchestrator.enforce()` 在落库前对模型提案做白名单 + 阶段 + 数量约束；`contracts.py` 的 `Interaction` 模型校验器拒绝非法组件类型与非法选项结构。

## 4. 验收标准逐条核查

| 验收项 | 结果 | 证据 |
|---|---|---|
| 注册组件按 manifest 可发现并正确渲染 | 满足 | `interactionRegistry.js` + `InteractionRenderer.vue` |
| 未知组件不崩溃且显示 fallback | 满足 | `resolveInteractionComponent` 回退 `InteractionStatusNotice` |
| 不允许模型输出事件处理器代码或任意 URL | 满足 | 无 `v-html`；组件仅渲染 `props`；`InteractionType` 白名单不含脚本/链接能力 |
| 键盘操作、移动端和主题切换可用 | 满足（代码层） | 交互用原生 `<button>`，含 `focus-visible` 样式与 `@media (max-width:640px)`；`ModeMenu` 有 `is-dark` 主题适配 |

## 5. 测试证据

- 后端：`tests/planning/test_planning_contracts.py` 覆盖组件类型白名单（未知 type 抛 `ValidationError`）。
- 前端：**无项目级自动化用例**（`node_modules` 之外的 `*.spec.ts`/`*.test.ts` 缺失），渲染安全目前靠「白名单 + 不用 v-html + Object.freeze」的静态设计保证。

## 6. 差距与风险

- **前端 e2e 缺失**：未知组件降级、键盘可达性、移动端适配等需 playwright/vitest 用例补齐（BLOCKED）。
- **组件版本化**：前端注册表无 `semver` 字段（契约层 `protocol_version` 已版本化，但单个组件无独立版本），当前以协议整体版本兜底。
- **懒加载**：组件为静态 import 而非 `defineAsyncComponent`，对当前组件规模（≤10 个）影响可忽略，规模扩大后再引入。
