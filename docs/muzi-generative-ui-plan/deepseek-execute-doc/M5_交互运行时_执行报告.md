# M5 · Interaction Runtime — 执行报告

状态：**CODE_PASS**（提交/跳过/审批/动作 + 幂等 + 版本 CAS + 状态机已落地；并发场景数据库级验证待跑）

## 1. 阶段目标

支持用户提交、跳过、取消、超时与恢复，并保持权限、事务和幂等闭环。

## 2. 现状审计结论

交互运行时已完整落地，校验链为：**鉴权 → 归属 → 幂等 → 版本 CAS → 动作白名单 → 目标定位 → 分发执行**。

- **状态机**：`InteractionStatus`（pending/submitted/processing/completed/failed/skipped/expired/superseded/cancelled）+ `PlanStatus`（understanding/clarifying/drafting/awaiting_approval/approved/ready_for_handoff/executing/completed/paused/cancelled/failed/superseded），终态不可逆由 `PLAN_TRANSITIONS` 约束。
- **幂等**：`interaction_submissions`（`client_submission_id` 唯一）+ `plan_actions`（`idempotency_key` 唯一）；同键重放返回原快照，同键不同内容 409。
- **并发 CAS**：`_store_revision` 用 `UPDATE ... WHERE current_revision = current` + `rowcount == 1` 保证并发只有一个写成功；`_owned_plan(for_update=True)` 加行锁。

## 3. 关键交付物

### 3.1 状态机（`contracts.py`）

```text
InteractionStatus: pending → submitted / skipped / expired / superseded / cancelled
PlanStatus: understanding → clarifying → drafting → awaiting_approval → approved
            → ready_for_handoff → executing → completed
```

`can_transition_plan()` + `PLAN_TRANSITIONS` 拒绝非法跳转（例如「未审批直接执行」被拒）。

### 3.2 统一动作协议（`contracts.py::InteractionAction`）

`action_type × target_type` 组合受 `ACTION_TARGETS` 白名单约束；卡片级动作必须带 `interaction_id`。动作清单：

```text
submit / skip
assumption_confirm / assumption_edit / assumption_reject
goal_edit / constraint_add / constraint_edit / constraint_remove
step_add / step_edit / step_remove / step_split / step_merge / step_reorder
revision_preview / revision_confirm / revision_rollback
```

### 3.3 恢复编排

提交结果以 `[Planning answer]` 回写 `ConversationMessage`，关联暂停中的 plan；`switch_mode` 只允许 `approved → agent`，`authorize_execution` 只允许 `ready_for_handoff → executing`，避免无意重复执行工具。

## 4. 验收标准逐条核查

| 验收项 | 结果 | 证据 |
|---|---|---|
| 同一次提交重试不重复调用模型/工具 | 满足 | `client_submission_id` 幂等（`submit_interaction` 先查重） |
| 过期、跨用户、旧 revision、越权 action 被拒绝 | 满足 | `expires_at` 检查 + `_owned_plan` + `_expect_revision` + `ACTION_TARGETS` |
| 用户跳过后运行策略符合模式约束 | 满足 | `skip_interaction` 仅落 `INTERACTION_SKIPPED`，状态转 `drafting` |
| 重启后 pending 交互可恢复 | 满足 | `PersistentInteraction` 持久化 + `get_pending_interaction` |
| 并发提交不会产生两个不同终态 | 满足（设计） | `for_update` + `_store_revision` 行级 CAS |

## 6. 差距与风险

- **数据库集成测试待跑**：`test_sql_store_integration.py` 依赖本机 PostgreSQL，需开启环境变量并跑通，才能把并发 CAS 从「设计成立」升为「实测成立」。
- **前端体验反馈**：`InteractionRenderer` 有 pending/loading/error/sent 状态；网络失败重试、过期提示的完整浏览器行为无自动化用例。
- **expires_at 默认未设置**：`apply_proposal` 创建交互时未默认赋过期时间（`expires_at` 为空即不过期）。若产品需要「交互超时失效」，需在落库时按策略赋值。
