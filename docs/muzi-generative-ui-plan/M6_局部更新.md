# M6｜局部更新与版本控制

## 阶段目标
让已展示组件可被安全增量更新，同时保持状态一致、用户输入不丢失。

## 前置条件
前序阶段验收通过；确认既有实现与本阶段契约兼容。

## 详细工作包
### M6-T01 更新协议
- 工作内容：限定 append_block、replace_props、set_block_status、remove_block；不允许任意脚本或 JSONPath 写入。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M6-T02 乐观并发
- 工作内容：base_revision、revision、block_id；旧 revision 冲突返回 409 并触发快照同步。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M6-T03 权限与所有权
- 工作内容：仅允许更新属于该消息/Run 的 block；交互提交后限制修改已确认选项。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M6-T04 Patch 校验
- 工作内容：先在服务端构造新状态、整体验证 Schema、原子持久化后发事件。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M6-T05 前端合并
- 工作内容：按 block_id 局部重渲染；保留输入焦点和未提交草稿；处理删除/替换的可访问性。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M6-T06 撤销和历史
- 工作内容：记录变更来源与审计；按需提供 revision history，不承诺所有更新都可逆。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M6-T07 边界测试
- 工作内容：并发更新、乱序、重复、旧组件版本、超大图表、删除待提交交互。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

## 关键验收标准
- [ ] 同一图表更新不重建整条消息
- [ ] 旧 revision 不能覆盖新版本
- [ ] 非法 patch 不改变数据库状态
- [ ] 输入中的交互组件不会因无关更新丢失草稿
- [ ] 重放 patch 后快照与实时结果一致

## 主要风险与防护
- 协议漂移：服务端 schema、客户端类型、测试样例统一生成或双向契约测试。
- 权限绕过：所有状态变更都在服务端复核，UI 组件不是授权凭证。
- 兼容性：加法迁移、feature flag、旧版 fallback、回滚路径。
- 竞态与重放：稳定 ID、事务、版本号、幂等键和事件序列。

## 统一工程约束
- 以现有 FastAPI / Vue 3 / PostgreSQL / Redis / SSE 为基线，先审计再修改；不得以规划推断当前实现状态。
- 后端是身份、授权、交互状态和事件序列的唯一可信来源；模型输出一律视为不可信输入。
- 协议必须版本化，旧客户端能安全降级；所有写操作具备鉴权、资源归属、幂等和审计。
- 每个阶段均需单元、集成、端到端、安全、兼容性测试；没有证据不得标记 ACCEPTED。
- 不擅自修改 Ask/Plan/Agent 现有语义，不以新 UI 协议替代 Runtime 权限边界。

## 阶段交付要求
- 提交架构决策记录（ADR）、协议/数据库迁移说明、测试报告、演示录屏或截图、回滚方案。
- 明确 CODE PASS、UAT PASS、PRODUCTION READY 三种不同状态。
- 每项验收需列出可复现命令、测试用例编号、预期结果、实际证据和已知限制。
