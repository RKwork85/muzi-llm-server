# M3｜模型自主选择 UI 组件

## 阶段目标
让模型在受控能力目录内决定是否需要 UI、选择组件及布局，并在失败时退回文本。

## 前置条件
前序阶段验收通过；确认既有实现与本阶段契约兼容。

## 详细工作包
### M3-T01 决策边界
- 工作内容：模型负责表达意图和选择；后端决定授权、风险和执行；不把 UI 选择等同工具调用授权。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M3-T02 能力上下文
- 工作内容：根据用户意图、模式、客户端能力、上下文预算提供精简组件清单与样例。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M3-T03 结构化生成
- 工作内容：定义 UIPlan/blocks 输出契约；优先使用结构化输出或受限工具调用，禁止直接执行生成代码。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M3-T04 组件选择策略
- 工作内容：文本优先；只有数据对比、澄清、确认、进度等场景才选 UI；限制组件数量和嵌套。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M3-T05 校验与修复
- 工作内容：服务端校验、一次受控修复或降级；记录 validation_error 而非静默丢弃。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M3-T06 布局规则
- 工作内容：有限布局 DSL（stack/grid/section），限制深度、列数、响应式规则；不得任意 CSS。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M3-T07 评测集
- 工作内容：构建不少于 40 个场景：问答、澄清、计划、图表、工具结果、拒绝、空数据、冲突、越权。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

## 关键验收标准
- [ ] 简单问答不强制生成卡片
- [ ] 适合的任务生成有效组件，结构通过 Schema
- [ ] 无权限组件无法输出为可执行 UI
- [ ] 模型异常/JSON 不完整时降级为可读文本
- [ ] 评测记录选择准确率、无效率、延迟、Token 成本

## 主要风险与防护
- 协议漂移：服务端 schema、客户端类型、测试样例统一生成或双向契约测试。
- 权限绕过：所有状态变更都在服务端复核，UI 组件不是授权凭证。
- 兼容性：加法迁移、feature flag、旧版 fallback、回滚路径。
- 竞态与重放：稳定 ID、事务、版本号、幂等键和事件序列。

## 统一工程约束
- 以现有 FastAPI / Vue 3 / PostgreSQL / Redis / SSE 为基线，先审计再修改；不得以规划推断当前实现状态。
- 后端是身份、授权、交互状态和事件序列的唯一可信来源；模型输出一律视为不可信输入。
- 协议必须版本化，旧客户端能安全降级；所有写操作具备鉴权、资源归属、幂等和审计。
- 每个阶段均需单元、集成、端到端、安全、兼容性测试；没有证据不得标记 ACCEPTED。
- 不擅自修改 Ask/Plan/Agent 现有语义，不以新 UI 协议替代 Runtime 权限边界。

## 阶段交付要求
- 提交架构决策记录（ADR）、协议/数据库迁移说明、测试报告、演示录屏或截图、回滚方案。
- 明确 CODE PASS、UAT PASS、PRODUCTION READY 三种不同状态。
- 每项验收需列出可复现命令、测试用例编号、预期结果、实际证据和已知限制。
