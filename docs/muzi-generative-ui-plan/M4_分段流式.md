# M4｜分段流式与事件恢复

## 阶段目标
实现文本增量、组件独立就绪、事件重放和断线恢复，不依赖解析半截 JSON。

## 前置条件
前序阶段验收通过；确认既有实现与本阶段契约兼容。

## 详细工作包
### M4-T01 事件模型
- 工作内容：run.started、block.open、text.delta、block.ready、block.failed、interaction.required、run.waiting、run.completed、ui.snapshot。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M4-T02 组装边界
- 工作内容：模型 Token 流与客户端 SSE 事件流解耦；组件完整校验后才发布 block.ready。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M4-T03 序列化
- 工作内容：每会话/Run 明确顺序域，event_id 单调递增、block_id 稳定；支持 Last-Event-ID 或 cursor。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M4-T04 持久化与 Outbox
- 工作内容：事务内写状态与待发布事件，异步发送；定义至少一次投递与前端去重。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M4-T05 快照恢复
- 工作内容：服务端快照 + cursor 后续增量；丢失事件、过期 cursor、版本不匹配时全量重同步。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M4-T06 前端 Reducer
- 工作内容：幂等 applyEvent，乱序缓冲或拒绝，重复事件忽略，组件局部更新。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M4-T07 背压和资源限制
- 工作内容：心跳、超时、最大队列、慢客户端、取消、重连退避、事件保留期限。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

## 关键验收标准
- [ ] 断线重连后 UI 与服务端快照一致
- [ ] 重复/乱序事件不会重复组件或覆盖新状态
- [ ] block.ready 前不展示非法未完成组件
- [ ] 工具结果延迟时文本仍可持续流式展示
- [ ] 多实例部署事件可恢复

## 主要风险与防护
- 协议漂移：服务端 schema、客户端类型、测试样例统一生成或双向契约测试。
- 权限绕过：所有状态变更都在服务端复核，UI 组件不是授权凭证。
- 兼容性：加法迁移、feature flag、旧版 fallback、回滚路径。
- 竞态与重放：稳定 ID、事务、版本号、幂等键和事件序列。

## 统一工程约束
- 以现有 FastAPI / Vue 3 / PostgreSQL / Redis / SSE 为基线，先审计再修改；不得以规划推断当前实现状态。
- 后端是身份、授权、交互状态和事件序列的唯一可信来源；模型输出一律视为不可信输入。
- 协议必须版本化，旧客户端能安全降级；所有写操作具备鉴权、资源归属、幂等和审计。
- 每个阶段均需单元、集成、端到端、安全、兼容性测试；没有证据不得标记 ACCEPTED。
- 不擅自修改 Ask/Plan/Agent 现有语义，不以新 UI 协议替代 Runtime 权限边界。

- 明确 CODE PASS、UAT PASS、PRODUCTION READY 三种不同状态。
- 每项验收需列出可复现命令、测试用例编号、预期结果、实际证据和已知限制。
