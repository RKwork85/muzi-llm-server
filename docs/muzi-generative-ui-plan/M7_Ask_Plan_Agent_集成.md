# M7｜Ask / Plan / Agent 集成

## 阶段目标
统一三模式的 UI 协议与交互体验，同时保留各自 Runtime、权限和审批边界。

## 前置条件
前序阶段验收通过；确认既有实现与本阶段契约兼容。

## 详细工作包
### M7-T01 能力矩阵
- 工作内容：列出三模式允许组件、工具、状态转移、用户确认语义；模式切换需明确授权。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M7-T02 Ask 接入
- 工作内容：普通问答、分析图表、澄清选择；不可因为 UI 事件绕过 Ask 工具限制。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M7-T03 Plan 接入
- 工作内容：交互式需求收集、方案 revision、审批与交接；复用已有 Plan 持久化，不创建平行真相源。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M7-T04 Agent 接入
- 工作内容：任务进度、工具结果、审批、暂停/恢复、取消；高风险操作必须走独立授权流程。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M7-T05 交接协议
- 工作内容：plan_id/revision、source_run_id、target_run_id、approved_scope、handoff_event；后端重核资源归属。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M7-T06 共享编排
- 工作内容：共享 UI Registry/Event/Interaction 服务，但模式策略和工具执行边界保持独立。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M7-T07 迁移与灰度
- 工作内容：Feature flag、旧消息兼容、按模式灰度、指标监控、快速回滚。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

### M7-T08 端到端演练
- 工作内容：Ask 澄清→Plan 修订确认→Agent 执行→中断恢复→结果回显，全链路审计。
- 交付物：设计/代码变更、测试用例、审查记录。
- 完成定义：可演示、可测试、可回滚；异常路径明确。

## 关键验收标准
- [ ] Ask/Plan/Agent 均可展示混合 Block
- [ ] Plan 只读边界无法被交互事件绕过
- [ ] 未审批的 Plan 不得进入 Agent 写操作
- [ ] 切换模式后交互和事件链路可追溯
- [ ] 跨进程重启、断线重连、撤权均正确处理

## 主要风险与防护
- 协议漂移：服务端 schema、客户端类型、测试样例统一生成或双向契约测试。
- 权限绕过：所有状态变更都在服务端复核，UI 组件不是授权凭证。
- 兼容性：加法迁移、feature flag、旧版 fallback、回滚路径。
- 竞态与重放：稳定 ID、事务、版本号、幂等键和事件序列。

## 统一工程约束
- 以现有 FastAPI / Vue 3 / PostgreSQL / Redis / SSE 为基线，先审计再修改；不得以规划推断当前实现状态。
- 后端是身份、授权、交互状态和事件序列的唯一可信来源；模型输出一律视为不可信输入。
- 协议必须版本化，旧客户端能安全降级；所有写操作具备鉴权、资源归属、幂等和审计。
- 每个阶段均需单元、集成、端到端、安全、兼容性测试；没有证据不得标记 ACCEPTED。
- 不擅自修改 Ask/Plan/Agent 现有语义，不以新 UI 协议替代 Runtime 权限边界。

## 阶段交付要求
- 提交架构决策记录（ADR）、协议/数据库迁移说明、测试报告、演示录屏或截图、回滚方案。
- 明确 CODE PASS、UAT PASS、PRODUCTION READY 三种不同状态。
- 每项验收需列出可复现命令、测试用例编号、预期结果、实际证据和已知限制。
