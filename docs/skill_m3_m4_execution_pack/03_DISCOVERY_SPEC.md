# 03 · M3 Discovery 详细规格

## M3.1 Discovery Domain

先检查 M0–M2 现有协议，尽量复用。只在确有缺口时增加最小契约。

概念：
- `DiscoveryRequest`：用户任务文本、调用场景（chat/agent）、可选明确 skill_id、策略模式、可选上下文提示。
- `SkillCandidate`：skill_id、名称、description、版本、来源/作用域、匹配分数、匹配理由、可用状态。
- `DiscoveryResult`：候选列表、选择建议、是否需要澄清、过滤/拒绝摘要、策略版本。
- `DiscoveryDecision`：none / recommend / select / explicit。
- `DiscoveryPolicy`：自动匹配阈值、候选上限、是否允许多 Skill、显式选择规则。

不要把用户身份作为可被客户端随意指定的权威字段。身份来自服务端认证上下文。

## M3.2 Metadata Search

- 优先使用现有 FileSkillRegistry 元数据索引。
- 先检查索引字段、查询能力、存储结构和性能，不要未经测量就增加数据库或向量库。
- 至少支持名称、description、tags（若协议已有）、适用场景等字段。
- 过滤 owner/tenant/状态/作用域必须在服务端完成。
- 搜索结果只包含元数据，不读 `SKILL.md` 正文。
- 对损坏索引、重复记录、缺失目录提供可观测错误，不泄漏其他用户记录是否存在。

## M3.3 Intent Matching

优先采用可解释、可测试的分层策略：
1. 显式 skill_id / 用户明确指定。
2. 精确名称或别名匹配（若现有协议支持）。
3. tags / description 关键词匹配。
4. 可选语义匹配扩展点。

不得为了“智能”默认调用额外 LLM 分类器；如现有 LLM 抽取能力可复用，必须定义成本、超时、失败回退和隐私边界，并由用户批准后实施。

匹配必须能返回：
- score（明确范围，例如 0–1）
- reasons（机器可读原因码 + 可读解释）
- matched_fields
- policy_version

分数不是授权。低置信度时推荐或询问，不应自动激活。

## M3.4 Candidate Ranking

建议排序因素（需根据现有数据字段确定）：
- 显式指定优先级最高，但仍需权限校验。
- 可用状态优先。
- 语义/关键词相关性。
- 精确名称和 tags 匹配。
- 同分时使用稳定次序（例如规范化名称、skill_id），保证可复现。

必须：
- 去重（同一 skill_id/version 不重复）。
- 限制候选数量。
- 解释排序原因。
- 处理相互冲突或描述高度重叠的候选。
- 不允许跨用户候选参与排序。

## M3.5 Discovery Policy

支持至少四种调用模式：
- `AUTO`：自动发现候选；只有超过明确阈值且符合策略时才提出选择建议。
- `RECOMMENDED`：只给出候选建议，不加载正文、不激活。
- `EXPLICIT`：用户明确指定；仍执行身份、所有权、状态、版本检查。
- `DISABLED`：不发现、不加载 Skill，保持旧行为。

注意：AUTO 发现到候选 ≠ 自动加载。选择决策与加载动作必须是两个独立步骤。策略应可配置、可测试、带版本号。

## M3.6 Lazy Loading

仅对最终选择的 Skill 调用 loader。Loader 必须：
- 重新读取 Registry 当前记录。
- 校验 owner 和当前 principal。
- 校验安装状态/可用状态。
- 固定明确版本。
- 校验包目录在允许根目录内，防止路径穿越/符号链接逃逸。
- 校验 `SKILL.md` 存在、大小上限、编码和 frontmatter。
- 计算正文摘要（建议 SHA-256），记录加载时版本和摘要。
- 对损坏文件 fail closed。
- 不执行 scripts/ 下任何文件。

正文作为不可信指令数据，注入模型上下文时必须用明确边界包装，并声明其不能覆盖系统策略。

## M3.7 Legacy Adapter

- `research`、`polish`、`minutes`、`weekly` 保持原有调用方式可用。
- 先检查这些提示在 Chat 中的真实消费位置。
- 可提供统一适配器，但不得直接删除旧常量、改变语义或强制迁移数据。
- 新注册表和旧提示之间若出现同名冲突，定义明确优先级并记录兼容行为。
- 迁移必须是可逆的；本阶段不要求把四条提示持久化成用户 Skill。

## M3.8 Tests

覆盖：
- 正常匹配、无匹配、多个候选、同分排序。
- 显式选择、推荐模式、禁用模式。
- 不同用户隔离、状态过滤。
- metadata-only（可通过 spy/mock 断言正文读取未发生）。
- 只有选择后才 load。
- 加载时二次授权校验。
- 版本变化、文件缺失、损坏 frontmatter、超大正文、路径穿越。
- 旧四条提示兼容。
- 搜索异常和超时降级。

## M3 Definition of Done

- Discovery 只访问元数据。
- 选择前正文读取次数为 0。
- 跨用户信息不泄漏。
- 结果排序稳定且有理由。
- 四种模式行为明确。
- 旧提示保持兼容。
- M3 专项测试通过。
