# 00 · 项目基线与保护范围

## 1. 路径与工作区

目标后端：`muzi-llm/muzi-llm-server`。执行前由 Cursor 确认当前打开目录、实际绝对路径、Python 包入口、应用启动入口和测试配置。

不得把 `muzi_project/muzi-llm-server` 当成真实路径。

## 2. 已完成能力（M0–M2）

已知完成内容：
- Skill 领域模型、状态机和协议。
- `FileSkillRegistry`：解析 `SKILL.md`、扫描目录、导入 ZIP、查询和卸载。
- Skill 正文保留在包目录，索引只保存元数据。
- 同一用户下同名冲突；其他用户不能读取该记录。
- 组织/项目作用域先拒绝写入，因为当前库没有对应成员表。
- 第三方脚本仅保存，不执行。
- 安装状态和任务激活状态分离；禁用不改正在使用的版本。

已知兼容项：
- `app/prompts/skills.py` 中 `research`、`polish`、`minutes`、`weekly` 四条提示继续可用。

## 3. 已知测试基线

- `tests/skills`：15 项通过。
- 全量测试历史结果：307 passed、10 skipped、2 failed。
- 两个失败位于 `tests/database/test_metadata.py`，原因是旧测试仍按九张业务表计数，而模型已有 MCP 表。
- 以上是用户提供的历史结果，不代表本次执行时仍是相同结果。Cursor 必须重新运行并记录本次真实结果。
- 不得为了让全量测试通过而修改数据库表、MCP 模块或旧表数量断言。若失败仍存在，应作为已知基线差异单独报告。

## 4. 保护范围

本阶段禁止：
- 修改 MCP、插件、代码执行相关文件，除非只读审查证明必须接入；如确有必要，先说明最小改动、影响和回滚方案，等待用户批准。
- 删除、重命名或迁移四条旧提示。
- 覆盖 `docs/phase3/`。
- 重构整个 LLM Provider、Chat、Agent、数据库或任务系统。
- 添加第三方 Skill 脚本执行。
- 擅自创建 Git 仓库、提交、分支、标签或提交检查点。
- 擅自引入组织/项目成员关系或绕过当前拒绝策略。
- 为追求“架构整洁”而大规模移动文件。

## 5. 不变量

1. 所有查询必须基于服务端身份上下文，不信任请求体传入的 user_id/owner_id。
2. Discovery 只返回当前调用者有权访问的候选。
3. 未选择的 Skill 不读取正文。
4. 加载时必须重新验证所有权、状态、版本和文件完整性，不能只相信之前的候选结果。
5. 激活任务固定具体 Skill 版本及内容摘要。
6. 禁用或更新 Skill 不得静默改变已激活任务快照。
7. Skill 指令是非可信输入，不可覆盖系统策略或授权边界。
8. Skill 与 Tool、Agent、MCP 是不同概念，不得混为一谈。
9. 不执行脚本，不开放任意文件、网络或宿主机访问。
10. 所有状态转换必须由领域规则控制并可测试。
