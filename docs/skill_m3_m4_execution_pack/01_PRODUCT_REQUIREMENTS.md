# 01 · M3 + M4 产品需求

## 目标

完成一条可用、可测试、可追踪的 Skill 使用链路：

用户消息 / Agent 任务
→ Discovery 查询元数据
→ 过滤不可用或无权访问的 Skill
→ 匹配和排序候选
→ 按策略决定不使用、推荐或明确选择
→ 仅对选中的 Skill 加载正文
→ 创建任务级版本快照
→ 组装模型上下文
→ 通过统一适配层接入 Chat / Agent
→ 记录结果、状态和错误。

## 核心用户体验

- 用户提出普通问题：没有必要时不加载 Skill，正常对话。
- 用户提出特定专业任务：发现一个或多个候选 Skill，按策略选择。
- 用户明确指定 Skill：验证权限、状态和版本后加载；不能因为明确指定而绕过安全检查。
- 多个 Skill 适用：按确定性规则排序，必要时返回多个候选；不允许无说明地任意选择。
- 没有匹配：返回空结果并继续普通 Chat/Agent 流程。
- Skill 正文引用资源：M4 只提供受控资源解析接口；资源按需读取，不预加载整个包。
- Skill 加载失败：清晰失败或降级，不得注入半截内容。

## 范围内

- Discovery 请求/结果契约。
- 元数据搜索和候选过滤。
- 意图匹配、排序、策略。
- 懒加载和加载校验。
- 任务级 Skill 激活和版本快照。
- 上下文构建。
- 受控引用资源读取。
- Runtime 生命周期、取消、失败状态。
- Chat/Agent 统一适配。
- 结构化日志、错误码、测试和文档。

## 明确不在范围内

- 执行 Skill 内的 Python、Shell、JavaScript 或其他脚本。
- 建立完整容器沙箱、网络策略和系统级权限模型（M5）。
- 平台级 Skill 市场、审核后台和计费。
- 组织/项目共享权限（当前无成员关系模型）。
- 对现有 Agent 规划器、工具执行器或 MCP 系统进行重写。
- 自行训练分类模型或引入外部向量数据库，除非审查证明现有能力无法满足且用户批准。

## 完成定义

M3 与 M4 的代码、测试、接口、文档和集成链路均完成；M3 与 M4 各自的验收项分别给出 PASS / FAIL / BLOCKED；所有未完成项、风险和已知基线失败如实披露。
