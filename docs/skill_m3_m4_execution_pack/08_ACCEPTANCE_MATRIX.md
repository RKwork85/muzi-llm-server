# 08 · M3 + M4 验收矩阵

每项标记 PASS / FAIL / BLOCKED / NOT APPLICABLE，并附测试命令、结果摘要和证据位置。没有运行的测试不能标记 PASS。

## M3 Discovery

| ID | 验收项 | 必须证据 |
|---|---|---|
| D-01 | 元数据检索不读取正文 | spy/mock 或文件访问计数测试 |
| D-02 | 当前用户隔离 | 双用户测试 |
| D-03 | 禁用 Skill 不会自动命中 | 状态过滤测试 |
| D-04 | 无匹配正常返回空结果 | 单测 |
| D-05 | 多候选稳定排序 | 同输入重复结果一致 |
| D-06 | 匹配理由可解释 | reason_codes 测试 |
| D-07 | AUTO/RECOMMENDED/EXPLICIT/DISABLED 区分正确 | 策略矩阵测试 |
| D-08 | 选择前不加载正文 | 读取次数为 0 |
| D-09 | 加载前二次校验权限/状态/版本 | 竞态测试 |
| D-10 | 旧四条提示兼容 | 回归测试 |

| R-08 | 资源按需读取 | read count 测试 |

## 一票否决

任意一项发生，整体不得验收：
1. 跨用户读取或激活其他用户 Skill。
2. Discovery 为了匹配而批量读取所有正文。
3. 未选择 Skill 就加载或激活。
4. 未授权 Skill 被激活。
5. 激活任务使用的版本/摘要无法确定。
6. Skill 正文能够覆盖系统策略或绕过服务端权限。
7. M3/M4 执行了第三方脚本。
8. Chat 和 Agent 各自维护不同的核心 Discovery/Loader/Runtime 逻辑。
9. 为实现 M3/M4 破坏 MCP、插件、代码执行等既有未提交改动。
10. 把未运行测试、跳过测试或已知失败写成通过。

## 测试报告必须包含

- 执行环境、Python 版本、依赖版本。
- 实际运行命令。
- M3 专项测试结果。
- M4 专项测试结果。
- Chat 集成结果。
- Agent 集成结果。
- 全量测试结果。
- 已知基线失败对比。
- 新增失败及原因。
- BLOCKED 项及阻塞条件。
- 代码变更文件清单。
- 未修改的保护范围确认。
- Git 状态（如目录非 Git 仓库，明确写明）。
- 结论：CODE PASS / ACCEPTED / PRODUCTION READY 三者分开。
