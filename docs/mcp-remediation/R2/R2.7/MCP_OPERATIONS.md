# 运行与故障

## 已经在本地证明

- 开发环境的 `/ready` 仍只要求 API Key。
- 生产就绪判断在密钥无效或数据库授权未就绪时返回 `mcp_key_invalid` 或 `database_unavailable`。
- 非幂等调用超时只发出一次，审计状态是 `unknown`，不重试。
- 幂等读取超时会再试一次。
- 写入已经开始后取消，审计状态是 `unknown`。取消只停止等待，不表示外部动作已撤回。
- 一个连接器熔断不会关掉另一个连接器。熔断打开后先进入半开，只放行一次试探。
- Agent 任务超过清理等待时间后仍会记成 `cancelled`。随后返回的成功结果不会覆盖这个终态。
- SSE 订阅发现断开后结束订阅。当前 httpx ASGI 测试传输要等响应结束才发出 disconnect，所以断开行为用订阅生成器的直接测试证明，没有伪造成一次真实断连。

## 没有做的真实故障

- 没有停止本机 PostgreSQL。
- 没有停止 Redis。MCP 授权不读取 Redis；Redis 故障不会单独改变授权表，但没有做真实断连实验。
- 没有杀掉独立的 MCP 子进程做恢复演练。
- 没有对远程 MCP 服务做真实不可用演练。协议超时和会话错误仍由既有假服务测试覆盖。

这些项目是 BLOCKED。
